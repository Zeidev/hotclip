# HotClip v0.40.0 — 运镜不再抖,拼缝不再断声,镜头终于有节奏
## 问题在哪
三件事,前两件是「画面/声音到手了但不对」,第三件是「素材有了但没下刀」:
- **运镜在抖**。crop 与 zoompan 都把移动窗口的位置对齐到色度网格(yuv420p →
  2 源像素):`vf_crop.c` 在没有 `exact=1` 时做 `s->x &= ~((1 << hsub) - 1)`,
  `vf_zoompan.c` 先把窗口宽 `trunc` 成整数再用 `log2_chroma_w` 掩码盖住 x。片子的
  几何是 606×1080 → 1080×1920,即 **1 源像素 = 1.78 输出像素**,窗口于是「先冻住
  几帧、再跳 3.56 输出像素」。合成点图案上实测就是 **26 帧纹丝不动、随后一跳
  3.7 像素** —— 正是闪现 punch 和呼吸 zoom 里看到的抖。
- **拼缝在断声**。跳剪的接缝是画面的硬切,声音原来也在同一刻硬切、两侧各加 30ms
  淡入淡出,而接缝借的那段静音明明就在手边。4 秒合成片实测:接缝处最低 RMS
  **0.0104**(基准 0.0530),凹陷宽 60ms —— 听感就是「接缝上被凹了一刀」。
- **节奏、画幅、速度只有参数没有实现**。品类没有任何镜头时长目标(一段长镜头
  从头到尾不换画面),竖版只有中心裁切,闪现也只有固定速度。
## 运镜落在超采样帧上(`autozoom.ts` / `cut.ts` / `reframe/track.ts`)
- 窗口位置改在 **lanczos 2× 中间帧**上决定,并转成 `yuv444p`:`log2_chroma_w = 0`
  让两个滤镜的 2 像素掩码一起失效,剩下的唯一量化是 **1 中间像素 = 0.89 输出
  像素**。`zoompan` 的 z、居中、`d=1`、`fps`、`s` 一个都没改。
- 带摇镜的裁窗:先取 `cropW+2` 的窗口 `floor(X)-1` 并 `exact=1`,亚像素余量作为
  超采样网格上的第二次 crop 补回;固定框、居中竖版、横版三条路径只要超采样级。
  合成是**单调**的(`floor(X)` 进一格、余量同时退一格),不会往回跳。
- 12 MP 以上的中间帧(4K 横版)退回 1,行为与旧版逐字节一致。
- 合成点图案 A/B(同一批帧、同一套测量):punch 1.00→1.10 maxDev **3.19 → 0.82
  输出像素**(反向跳 14 → 0),呼吸 zoom 1.00→1.06 **3.33 → 0.70**(y 3.09 →
  0.65),跟随摇镜 **2.84 → 1.05 像素**(冻帧 29 → 0)。锐度(平均 |Laplacian|)略升,
  首帧构图不变 —— 既没变软也没重新取景。
- `RENDER_CACHE_VERSION` → 2:旧图缓存出来的成片就是会抖的那版,不能复用。
## 拼缝:L-cut / J-cut(`cut.ts` / `export.ts`)
- **画面照样硬切**;声音以切点为中心 acrossfade 0.3 秒(每侧 0.15 秒),借的正是
  被切掉的那段静音。交叠只吃掉静音,**总长与每个词的时间都原地不动**。
- 缝里没有静音可借(零静音的节奏刀、极短段)就退回硬接:`seamCrossfades` 逐缝取
  `min(0.15, 缝宽, 前段/2, 后段/2)`,不足 0.02 秒记 0,缝与缝之间互不影响。
- 真机 A/B(4.000 秒合成片:2 秒有声 / 0.6 秒静音 / 2 秒有声):新旧都是 **4.000
  秒**、新版音频 **4.011 秒**(长度中性)、接缝最低 RMS **0.0387**(基准 0.0530,
  旧版 0.0104)、凹陷 180ms(旧 60ms)、拼接窗主频仍是 **440Hz**(音高没被重采样
  带走)、画面 59 帧红 / 60–61 帧蓝(还是硬切)。五项判据全过。
- 缓存键的 implementation 由 `export-base-v1` 提到 `v2`:选项没变、出来的字节变了,
  旧跳剪缓存不能端上来。
## 节奏与画幅(`gaps.ts` / `genre.ts` / `fill.ts` / `speed-ramp.ts` / `qa.ts` / `diarize.ts`)
- **品类节奏目标**:段长超过目标时,在目标附近**信息最稀**的那条词间缝(词/秒)下刀,
  缝里必须真是静音(笑声/掌声的峰值说了才算),切口取缝的中点 —— 绝不在词里下刀;
  补出来的每一刀都是**零长度缺口**,音频取自同一段源,**总长与字幕时间轴一个字节
  不变**。
- **镜头密度曲线**:开场 3 秒切得密(信息密度最高处),收口 5 秒收紧,中段仍听品类档。
- **模糊填充**竖版(`fill.ts`,可选):整帧落在一份模糊压暗的自己上,而不是把画面
  中心裁掉。有运镜、有跟随、或源比例本来就对时仍走裁切 —— **裁切是默认**。
- **速度斜坡**给闪现(`speed-ramp.ts`,可选):`setpts` 放在 `subtitles` **之后**,
  烧进画面的字幕跟着一起加速;`atempo` 保音高。有斜坡时 `-t` 移到 `-i` **之前**,
  否则 1.4× 会把计划 3 秒的窗读成 4.2 秒源。
- `qa.ts` 增加节奏打点与整片单次解码度量(`edit-metrics.ts`,不再单独解码两遍);
  `diarize.ts` 增加 `speakerTurnsFromWords`;导出把 `fillMode` / `speedRate` 透传进
  cut options 与缓存键。
## 已知缺口
- 模糊填充与速度斜坡目前只能从 cut / 导出选项传进去,**渲染界面还没有开关**
  (单独一单在跟)。
- 本机完整套件仍有 1 项失败:`cover-quality.integration`(`candidatesRejected 1 <
  2`),它依赖的 `cover-quality.ts` / `cover.ts` / `binaries.ts` / `runFfmpeg` 本版
  均未改动,判定为本机 FFmpeg 环境问题(与 v0.39.1 同一项)。
- 本版不改提示词,没有真实 LLM 端点复跑。
## 验证
两套 tsconfig(`node` / `web`)类型检查通过;`npx vitest run` 本机 **1,766 项通过、
1 项跳过、1 项失败**(即上面的环境项)。运镜用合成点图案逐帧重心测量(punch /
呼吸 zoom / 跟随摇镜三条路径 + 锐度 + 首帧构图),拼缝用 4.000 秒合成片 A/B
(总长 / 音频长度 / 凹陷深度与宽度 / 音高 / 硬切),两个探针都留在 `.seamtmp/`
下(不提交)。
## English
**Why**: three things, the first two "the picture and the sound arrive but land
wrong". crop and zoompan both snap the moving window to the chroma grid (2
source px on yuv420p: `vf_crop.c` masks `s->x` unless `exact=1`, and
`vf_zoompan.c` truncates the window width then masks x with `log2_chroma_w`).
At 606×1080 → 1080×1920 one source pixel is 1.78 output px, so the window
freezes for a few frames and then leaps 3.56 output px — on a synthetic dot
that reads as 26 frozen frames and a 3.7 px jump, which is exactly the shake
seen in the flash-forward punch and the breathing zoom. Second, the jump-cut
seam hard-cut the audio at the same instant as the picture, then faded 30 ms on
each side, even though the removed silence was sitting right there: the seam's
minimum RMS measured 0.0104 against a 0.0530 reference, a 60 ms notch. Third,
rhythm, framing and speed existed only as parameters with nothing behind them.
**Fixes**: the window is now positioned on a lanczos 2× working frame in
yuv444p, where `log2_chroma_w = 0` disables both masks and the remaining grid
is 0.89 output px; a panning crop takes a `cropW+2` window at `floor(X)-1` with
`exact=1` and applies the sub-pixel remainder as a second crop on the
supersampled grid (a static frame, the centred vertical crop and the horizontal
path need only the supersampling stage), the composition is monotonic so it
cannot reverse, and a working frame over 12 MP (4K landscape) falls back to 1
and the old behaviour byte for byte. On the dot: punch maxDev 3.19 → 0.82 px
with reversals 14 → 0, breathing zoom 3.33 → 0.70 (y 3.09 → 0.65), tracker pan
2.84 → 1.05 px with frozen frames 29 → 0; sharpness improves slightly and the
first frame's framing is unchanged. `RENDER_CACHE_VERSION` goes to 2 so the
shaky cached renders are not served.
**Seams**: the picture still hard-cuts, but the audio crossfades 0.3 s centred
on the cut, borrowing only the removed silence, so total length and every word
time stay put; a seam with no silence to borrow (a zero-silence rhythm cut, a
very short segment) falls back to a hard join via `min(0.15, gap, prev/2,
next/2)`, rounded to 0 below 0.02 s, per seam. On a 4.000 s synthetic clip the
seam's minimum RMS goes 0.0104 → 0.0387 (reference 0.0530), the notch widens
60 ms → 180 ms, the seam window still peaks at 440 Hz, and the picture still
cuts between frames 59 and 60. The cache key's implementation string moves
`export-base-v1` → `v2`, because the option set is unchanged while the bytes are
not.
**Editing**: a genre rhythm target splits an over-long shot at the sparsest
real inter-word silence near the target (peaks decide it is silence; the cut
lands at the middle of the gap, never mid-word) with a zero-length gap, so
audio, total length and the caption timeline are untouched; a shot-density
curve cuts densely in the first 3 s and tightly at the close; an optional
blurred fill puts the whole frame on a blurred, dimmed copy of itself (crop
stays the default, and stays the path when there is a track or a zoom); an
optional speed ramp runs `setpts` after `subtitles` so burned captions speed up
with the picture and `atempo` keeps the pitch, with `-t` moved before `-i` so a
1.4× ramp does not read 4.2 s of a planned 3 s window. `qa.ts` gains pacing
punch points and `edit-metrics.ts` measures the finished clip in a single
decode pass.
**Known gaps**: the blurred fill and the speed ramp are reachable only from the
cut/export options — there is no switch in the render UI yet; the one local
failure, `cover-quality.integration` (`candidatesRejected 1 < 2`), is a local
FFmpeg environment issue whose dependencies are untouched here; no prompt
changed, so no live-endpoint rerun.
**Validation**: both tsconfigs typecheck clean; `npx vitest run` reports 1,766
passing, 1 skipped and the environment failure above. The camera moves are
measured frame by frame on a synthetic dot and the seam by an A/B render of a
4.000 s clip (length, audio length, notch depth and width, pitch, hard cut);
both probes live under `.seamtmp/` and are not committed.
