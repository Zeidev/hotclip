# HotClip v0.37.2 — 导入字幕本地修复 + 整轨时移 + 拉丁断行;冷开场补上自己的引文
## 问题在哪
创作者自己的字幕有三个断点:导入的 SRT/VTT 只要有一条重叠、倒序或零时长就被整体拒绝,
自己排好的字幕根本打不开;整条轨比音频早/晚几秒时只能逐条改时间;断行与阅读速度按
中文标定,土耳其语/英语常把行断在连词后面,中文语速下不告警的句子在拉丁语里其实读不完。
冷开场(高潮前置)这边:两条闪现问题让它在真实成片上几乎不出现或只截到半句话,
而「钩子句前置」在 162 条真实候选里一次都没触发——查下来不是守卫错,是选段提示词把
`hook` 定义成**片段首句**,拿它当前置等于把开场句重播。
## 导入字幕本地修复(`src/shared/subtitle-import.ts`)
- 新增 `repairSubtitleCues`(确定性、零 API):按开始时间重排;倒置区间对调;零时长补到
  0.7 秒可读下限(不越过下一条的开始,也不越过片长);重叠时把**后一条**的开始推到前一条
  的结束(保留后一句自己的窗口,不吞前一句);修完没有任何时间可言的条目丢弃。
- **文本一个字都不改**;健康轨道逐字节原样返回,且不产生任何报告字段(不制造噪声)。
- `parseSubtitleTranscript(text, format, durationSec, { repair: true })` 为显式开关,
  严格默认不变——已有调用方与 15 条旧断言原样通过。
- 所有真实导入入口都走 `repair: true`:IPC `hotclip:import-subtitle`、CLI
  `transcribe --subtitles`、MCP `transcribe_video`、浏览器 mock。
- 回执经工作台既有的「导入字幕」横幅显示(zh/en/tr 三语),CLI stderr 与 MCP 文本各加一行。
## 整轨时移(`shiftSubtitleCues` / `shiftSubtitleTranscript`)
- 整条轨按 `offsetSec` 平移,文本不动;越过 0 的头部钉在片头、超出片长的尾部裁掉(与导入
  同一边界);平移后没有任何时间窗的条目丢弃;`0` 偏移原样返回,不产生回执。
- 回执新增 `shiftedSec / shifted / clipped`,工作台横幅加秒数输入与「应用」。
- 会话存储保留被偏移删掉的段,改回去能重新插回——时移可撤销。
## 拉丁语断行与阅读速度(`src/core/subtitle.ts`)
- `groupWordsIntoLines` / `planReadableCaptions` 接收可选的 `AppLang`:`tr`/`en` 时行尾
  不落在连词/后置词上(`ve, bir, ile, ama, ki, de, da, bu, şu`),词本身不拆。
- 阅读速度上限按语言:土耳其语/英语 17 CPS,中文仍 20;中文路径与「不带语言」的默认
  逐字节不变,已有调用方输出不动。
- 导出、字幕叠加、SRT 调用点把 `uiLang(options.locale)` 透传下去。
## 冷开场:坐标、整句、以及它自己的引文
- **坐标**(`src/core/audio-peaks.ts`):峰值轨是源片绝对时间,而 `mapToOutputTime` 收的
  是切片相对时间——直接把绝对时间喂进去会多叠一次偏移,每个事件都落到所有保留段之外,
  跳剪成片上的「爆点闪现」因此从不触发。新增 `mapPeakEvents` 把每个峰配成
  `(srcSec, outSec)`:回源片切片用前者,运镜/音效打点用后者;被剪掉的空隙里的事件直接丢。
- **整句**(`flashWindow`):旧实现固定 0.2+0.5=0.7 秒,真实素材上只截到半句话
  (「...anlatsam」),观众看不懂发生了什么。改为两端吸附词边界、顺着句读(词间静音
  ≤ 0.45 秒)扩到整句、总长夹在 3 秒内;只认完整落在本保留段内的词;峰值落在无人声处
  (笑声/掌声)时不做词吸附,直接给下限窗——那时的画面本身就是钩子。
- **重复句**(`planColdOpen`):同一句在开头也出现过时,第一次命中会被 near-start 守卫
  判掉,整条合法候选白丢。现在从守卫边界外再找一次,中段那次仍然可用;跨边界命中仍按
  太近处理;常见路径仍只查一次。
- **为什么钩子前置在真实素材上不触发**:13 个项目、162 条真实候选实测,`planColdOpen`
  **100% 返回 null**。守卫不是原因:转写模式的选段提示词把 `hook` 定义成「片段的开场句」
  (`highlight/prompt.ts`),切片本身就是从句首开剪——146/149 条可定位的钩子逐字就是切片
  首句,首词延迟 0.00 秒,前置等于把开场句连着重播。守卫**保留**:降到 3 秒也只多放行
  3/162 条,却拿掉了防「开场句口吃」的地板。两条实测样例钉在测试里。
- **新增可选字段 `coldOpenQuote`**:选段时若「全片最炸的一句」不在开头,模型把它逐字写进
  这个字段(三语提示词 + JSON 形状都写清「不是首句才写,首句已经承担钩子就写空字符串」);
  解析(`parseSelections`)、`RawSelection`、`clip.meta`、桌面导出 IPC 全程带下去。导出
  优先用它,缺席时**逐字退回** `meta.hook`——旧项目文件、moment 通道的画面描述行为与
  改前完全一致(画面描述本来就匹配不到,安全地不前置)。
## 已知缺口(不在本版)
- **`coldOpenQuote` 没跑过真实 LLM**:115/162 只是几何天花板(「片段里有没有一句不在
  开头、又能当前置的整句」),模型实际会不会写、写得准不准,本机没有调用真实端点。
- **导入修复/整轨时移没在 Electron/IPC 里端到端跑过**:解析、修复、时移、回执都有单测,
  浏览器预览用 mock provider 验过横幅与「应用」的整条 UI;真实 FFmpeg 导入路径在本机被
  沙箱拒绝。
- 文字稿基本没有信息量的品类(dance/游戏/户外)走 moment 通道,`hook` 是画面描述而非
  引文,本版不试图把它变成引文——那些片子的开场仍交给「爆点闪现」。
本地验证:类型检查(node + web 两套配置)通过;1,538 项测试通过、12 项跳过。18 项
ffmpeg 用例失败全部是本机沙箱不能写系统临时目录(`Permission denied`)导致,与本版本无关。
## English
- **The gap**: an imported SRT/VTT track was rejected outright if a single cue
  overlapped, ran backwards, had zero length or sat out of order, so a creator's own
  subtitles could not be opened; a track that was simply offset had to be fixed cue by
  cue; and caption line breaks and reading speed were calibrated for Chinese, so
  Turkish and English lines broke after a conjunction and speeds a Latin reader cannot
  follow were never flagged.
- **Local subtitle repair**: `parseSubtitleTranscript` takes an opt-in
  `{ repair: true }`; `repairSubtitleCues` re-sorts by start, swaps inverted ranges,
  grows a zero-length cue to the 0.7s floor (bounded by the next cue and the source),
  pushes an overlapping cue's start to the previous cue's end and drops a cue left with
  no time. Text is never rewritten and a healthy track returns byte-for-byte with no
  report. Every real import path opts in; the receipt rides the existing
  imported-subtitles banner (zh/en/tr), the CLI stderr and the MCP text.
- **Whole-track time shift**: `shiftSubtitleCues` / `shiftSubtitleTranscript` move
  every segment and word by an offset, pin a head that would fall before zero, cut a
  tail past the source and drop a cue that loses its window; the banner gains a
  seconds field and Apply, and the session store keeps removed segments so the shift
  stays undoable.
- **Latin line breaks and reading speed**: the grouper and the readability planner take
  an optional language — Turkish/English lines never end on a conjunction or
  postposition, and the reading-speed ceiling is 17 CPS for Latin against 20 for
  Chinese; the Chinese and no-language paths are byte-identical.
- **Flash-forward was never firing on jump-cut clips**: peak events carry absolute
  source time while the output-timeline mapper expects clip-relative time, so every
  event landed outside the kept segments. `mapPeakEvents` now pairs each peak as
  `(srcSec, outSec)`.
- **Flash-forward was half a sentence**: the fixed 0.7s window cut "…anlatsam". The
  window now snaps to word boundaries, expands along pauses (≤0.45s) to the whole
  utterance, is capped at 3s, only uses words fully inside the kept segment, and keeps
  the bare window when the peak lands on laughter or applause.
- **Hook pre-roll**: a hook line that also occurs at the opening no longer discards the
  clip — the lookup is retried past the guard boundary. And the reason it never fired
  at all on real footage: across 13 projects and 162 hooked candidates `planColdOpen`
  returned null 100% of the time, because the transcript-mode prompt defines `hook` as
  the clip's opening line and clips are cut hook-first (146/149 match the clip's first
  words verbatim, with 0.00s of dead air in front). The guard stays — lowering it
  would recover only 3/162 and drop the anti-stutter floor. Instead selections can now
  carry an optional `coldOpenQuote` (the clip's most striking line, written only when
  it is not the first sentence); export prefers it and falls back to `meta.hook`
  verbatim, so old project files and moment-channel visual descriptions behave exactly
  as before. Geometric ceiling 115/162; the real LLM fill rate was not run.
- **Known gaps**: no real LLM run for `coldOpenQuote`; the repair/shift paths are
  covered by unit and browser-preview checks but not by a real Electron/IPC import
  (FFmpeg is blocked in the author's sandbox); moment-channel clips keep a visual
  description in `hook` and are left to the flash-forward opener.
