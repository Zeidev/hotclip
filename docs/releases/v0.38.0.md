# HotClip v0.38.0 — 标题与开场句有了强质检和就地返工;冷开场配上自己的过场;踩点剪切终于对上拍

## 问题在哪
三处都在「判据和真实时间轴对不上」这一件事上:

标题与开场句(kanca)一直在写**话题标签**(「Odada havalandırma var mı」)和
**语气词开头**(「Vallahi billahi.」「bi kardeşiniz var」),因为下游没有任何一层
分得清「标签」和「钩子」:写法只有五条路线、没有禁止句形、没有强制锚点;本地闸门
只抓格式缺陷(空/超长/套话开头/话题标签词/平台风险词);返工路径只有标题一条,
开场句完全没有。

踩点剪切(beat sync)自上线起**一次都没生效**:`planBeatSnap` 拿 BGM 的鼓点去比
`segment.startSec`,可两者不在同一个时钟上——鼓点来自从成片 0 秒铺满的音乐床
(`-stream_loop -1`),段起点是**源片绝对秒**(录播回放动辄 3000 秒开外),
两者之差永远等于「这条片在源里的位置」,于是每次都判「不在拍上」。

冷开场那边的过场音效是全局开关的下属,开关关掉后切口是硬的;预滚画面也没有任何运镜。

## 标题与开场句:写法收紧 + 本地质检 + 就地返工(`hook-craft.ts` / `hook-quality.ts` / `highlight/`)
- **写法**(`hook-craft.ts`,中英土三语原生):新增「禁止句形」——话题标签
  (「X nedir / X 是什么 / X hakkında」)、中立的是非问句、两条并排的中立陈述、
  「我在做X」式流程描述、无锚点标题;每个标题必须同时具备**锚点**(数字/专名/
  逐字引文)和**转向**(反差、代价或问题);追加自检句「先写三个候选再挑最狠的,
  写出来的句子读起来像新闻标题就重写」。
- **本地闸门**(`hook-quality.ts`):新增 `stage1Hook` 面,三个代码
  `hook-filler-open`(首词是语气词)、`hook-fragment`(小写/连词开头、不足四词、
  或长句的截断前缀)、`hook-interjection`(整句都是语气词);`stage1` 加三个**强度
  信号** `no-anchor` / `topic-label` / `flat-close`。这些信号**从不否决片段**,
  只表示「送去返工」;发布路径与既有代码的行为不变。
- **返工搭在第二遍审阅里**(`highlight/prompt.ts` / `highlight/detect.ts`):不额外
  调一次 LLM。每个候选块自带本地闸门备注(`Yerel kapı: başlık no-anchor; kanca
  hook-filler-open`),输出形状加 `hookFix`;采纳是**确定性**的——`hookFix` 必须在
  片段文本里**逐字**出现、且本地闸门的弱项代码**严格变少**才采纳;`titleFix`
  必须过掉硬代码且严格更强;被拒就保留原稿,坏返工不产生代价。
- **顺带修好冷开场**:`coldOpenQuoteText` 缺席时逐字退回 `hook`,所以开场句被修好,
  正片第一秒的前置句跟着变好,不需要新机制。

## 冷开场过场:whoosh 掐在接缝上 + 预滚推近(`sound-design.ts` / `autozoom.ts` / `export.ts` / `cut.ts`)
- whoosh 的峰值现在**正好落在冷开场接缝**上(提示音提前一个起音开始),并给正片首帧
  加一记低频撞击(impact thump)。
- 这对过场属于冷开场本身,所以**即使全局音效偏好关闭也会响**——它是切口的胶水,
  不是装饰。
- 迷你预滚用单条 `punchTo` 斜坡从 1.0 推到 1.1,正片保持原有取景;测试钉住配对位置、
  预算/尾部守卫、撞击混音电平与推近表达式。

## 踩点剪切:改在成片时间轴上判定(`beat.ts` / `gaps.ts` / `export.ts`)
- `planBeatSnap` 先把每个接缝换算到**成片时间**:`atSec = Σ_{j<i} dur_j − transitionSec·i`
  (与 `cut.ts` 里 xfade 接缝的位置一致),在成片上找最近的、**不晚于它**的鼓点,
  再把源片切点按同样的量往前挪——往前永远落进这次剪切本来就要删掉的静音里,
  所以不可能吃掉字。
- `detectFileOnsets` 现在回报 `analyzedSec`;新增 `repeatBeatGrid`:音乐床短于片段时
  按床长重复它的鼓点网格,一直铺到片段长度(此前 60 秒分析窗口之后的接缝永远踩不上)。
- 召回的守卫全部保留:不往前移、不吞掉前一段、不把一段压缩到 0.2 秒以下、单段/空网格不动。
- 测试改成**成片时间**的判据:同一组源片时间戳,只要成片接缝在拍上就不动;
  源片时间戳看起来像拍、成片接缝不在拍时,依然要挪(这正是旧代码永远不触发的场景);
  另加交叉淡化偏移与网格重复两组用例。

## 已知缺口(不在本版)
- **踩点剪切没有在真实音乐床上端到端验证**:真实 FFmpeg 解码在本机沙箱被拒
  (`Permission denied`),所以 `analyzedSec` 的测量与「短床循环」只过了单测;
  某次真实导出里接缝实际挪了几次,本机拿不到证据。
- **标题/开场句返工没有跑真实 LLM 端点**:离线预演(3 个真实项目、81 条标题/81 条
  开场句)标出 11 条标题、37 条开场句需要返工,这是闸门的证据,不是模型实际改写
  质量的证据。
- **过场 whoosh/撞击只做过单测与混音电平断言**,没有在真实片子上听过。

本地验证:两套 tsconfig 类型检查通过;1,577 项测试通过、12 项跳过;18 项 ffmpeg
用例失败全部是本机沙箱不能写系统临时目录(`Permission denied`)的老基线,与本版无关。

## English
- **Why**: three symptoms, one cause — a judgement was made on the wrong clock. Titles
  read as topic labels ("Odada havalandırma var mı") and the `hook` field as filler
  openers ("Vallahi billahi.", "bi kardeşiniz var") because the doctrine had no banned
  shapes and no anchor requirement, the local gate only caught format defects, and only
  the title had a repair path. Beat sync never fired at all: `planBeatSnap` compared BGM
  onsets against `segment.startSec`, but the bed is looped from output 0 while a segment
  start is an absolute source second, so the difference was always the clip's position in
  the source. And the cold open carried no transition of its own.
- **Title and hook doctrine**: the writing rules now list the shapes that count as
  unwritten (topic label, neutral yes/no question, two flat statements, "I'm doing X"
  process narration, an anchor-less title) and demand both an anchor (a number, proper
  name or verbatim quote) and a turn (contrast, cost or question), plus a pre-submit
  self-check — natively in zh/en/tr.
- **Local gate**: a new `stage1Hook` surface flags `hook-filler-open`, `hook-fragment`
  and `hook-interjection`; `stage1` gains `no-anchor`, `topic-label` and `flat-close` as
  strength signals. Signals never veto a clip — they only ask for repair, so existing
  codes and the publish path behave exactly as before.
- **Repair rides the second review pass** — no extra LLM call. Each candidate block
  carries its own gate note, the output shape gains `hookFix`, and adoption is
  deterministic: a `hookFix` is taken only when it sits verbatim in the clip text and
  strictly reduces the weakness count, a `titleFix` only when it clears the hard codes and
  is strictly stronger; a rejected repair keeps the original. Because `coldOpenQuoteText`
  falls back to `hook`, a repaired opener also fixes the cold open's first second.
- **Cold-open transition**: the whoosh now peaks exactly on the cold-open seam (the cue
  starts one rise ahead) and a low impact thump lands on the body's first frame; the pair
  belongs to the cold open itself, so it fires even with the global SFX preference off.
  The mini pre-roll zooms 1.0 → 1.1 through a single `punchTo` ramp while the body keeps
  its normal framing.
- **Beat sync on the output timeline**: each splice is located at
  `Σ_{j<i} dur_j − transitionSec·i` (the xfade junction in `cut.ts`), snapped back to the
  nearest beat at or before it, and the source cut moved by the same amount — backward
  always lands in silence the cut was already removing. `detectFileOnsets` now reports
  `analyzedSec` and `repeatBeatGrid` repeats a looping bed's grid out to the clip length.
  Guards unchanged: never forward, never swallow the previous piece, never collapse a
  piece below 0.2s.
- **Known gaps**: the snap path is unit-tested only — real FFmpeg decode is blocked in the
  author's sandbox, so `analyzedSec` and the loop repetition have no real-footage receipt.
  The title/hook repair was rehearsed offline (3 real projects: 11 of 81 titles and 37 of
  81 hooks flagged) but not against a real LLM endpoint, and the new whoosh/impact pair
  has only been checked by unit tests and mix-level assertions.
- Local validation: both tsconfigs typecheck clean; 1,577 tests pass, 12 skipped; the 18
  FFmpeg failures are the known sandbox baseline (`Permission denied` writing to the
  system temp directory) and are unrelated to this release.
